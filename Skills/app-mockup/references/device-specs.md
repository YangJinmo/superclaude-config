# 기기별 해상도 · 컷아웃 크기 참고표

CSS 프레임의 화면비(aspect-ratio)와 상단 컷아웃 종류/크기를 기종명만으로 바로 정할 때 쓴다. 표에 없는 신형 기종이 나오면 WebSearch로 해상도만 확인해서 이 표에 추가한다 (`{모델명} screen resolution pixels`).

## 아이폰 해상도 (물리 픽셀 W×H, 스케일 무관하게 화면비 계산에 사용)

논리 해상도(pt) 열은 스크린샷에 상태바가 없어 [노치 / 다이나믹 아일랜드 / 펀치홀 실측 크기]의 pt 근사치를 새로 그려 넣어야 할 때, `pt값 × (스크린샷 px 너비 / 이 열의 논리 너비)`로 실제 px 크기를 환산하는 기준으로 쓴다 (모두 @3x, 단 XR/11만 @2x).

## 노치 / 다이나믹 아일랜드 / 펀치홀 실측 크기

스크린샷에 상태바(시간·배터리·신호 아이콘)가 아예 없어서 컷아웃을 새로 그려야 할 때 이 절대 크기를 쓴다. 스크린샷에 상태바가 보인다면 이 표 대신 SKILL.md의 [갤럭시 전용 — 펀치홀] 실측 공식(상태바 높이 기반 60%)을 우선한다 — 실제 스크린샷에서 잰 값이 항상 이 근사표보다 정확하다.

### 아이폰 노치 (mm는 실측 보도자료 기준, pt는 1pt=163ppi 기준 환산치 `mm×6.417`)

| 세대 | 크기(mm, 폭×높이) | 환산 pt(폭×높이) | 대상 기종 |
|---|---|---|---|
| 구형(큰) 노치 | 약 35×5.3mm | 약 225×34pt | X, XS, XS Max, XR, 11, 11 Pro, 11 Pro Max, 12 계열(mini 포함), 12 Pro, 12 Pro Max |
| 축소 노치 (구형 대비 폭 -20%) | 약 26.8×5.35mm | 약 172×34pt | 13 계열(mini 포함), 13 Pro, 13 Pro Max, 14, 14 Plus, 16e |

pt 값은 논리 뷰포트(위 해상도 표의 스케일) 기준이므로, 실제 스크린샷 px 크기로 쓰려면 `pt × (스크린샷 px 너비 / 논리 pt 너비)`로 다시 스케일한다.

### 다이나믹 아일랜드 (14 Pro부터 17 Pro Max/Air까지 전 기종 동일 크기 — Apple이 세대별로 캡슐 자체 크기를 바꾼 적 없음)

- 평상시(유휴) 캡슐: 약 126×37.33pt — 디자인 커뮤니티에서 가장 널리 쓰이는 근사치(Apple이 공식 수치를 발표하지 않아 정확한 스펙은 아님). 목업에는 이 값을 사용한다.
- 참고용 세부값(라이브 액티비티 중 두 조각으로 갈라졌을 때): Pro 모델 좌우 조각 각 52.33pt, Pro Max 모델 각 62.33pt, 공통 높이 36.64pt — 평상시 모양엔 쓰지 말 것.
- 모양: 완전한 캡슐(pill, border-radius = height/2), 화면 정중앙 상단, 상단 여백은 위 해상도 표의 상태바 높이 기준(15 시리즈 기준 약 59pt 세이프에어리어 top) — 이 59pt는 모델마다 조금씩 다를 수 있지만 Apple이 세대별 정확한 값을 공개하지 않으므로, 상태바가 없는 스크린샷에 새로 그릴 때는 전 다이나믹 아일랜드 기종에 공통으로 근사치로 써도 무방하다.

### 갤럭시 펀치홀 지름 (Samsung 공식 지원 페이지 기준)

| 모델 | 지름 |
|---|---|
| S23 / S23+ | 3.34mm (공식) |
| S23 Ultra | 3.75mm (공식) |
| 그 외 세대(S21/S22/S24/S25 등) | 공식 수치 미확인 — S23 값(약 3.3~3.8mm, Ultra가 더 큼)을 근사치로 쓰거나, 실제 스크린샷 기반 60% 공식을 우선 사용 |

mm 값을 스크린샷 px로 직접 환산하려면 기종 ppi(위 해상도 표의 px 대각선 ÷ 화면 인치)가 필요해 번거롭다. 대신 S23과 S23 Ultra 둘 다 지름/화면폭 비율이 약 5.1%로 거의 동일하게 나오므로, 상태바가 없는 스크린샷에서는 **목업 screen width의 약 5%**를 펀치홀 지름으로 바로 써도 대부분 자연스럽다 (SKILL.md [갤럭시 전용 — 펀치홀]의 "상태바가 아예 없는 경우" 참고).
